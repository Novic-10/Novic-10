This writeup details the forensic analysis of a compromised Linux server, identified as Ubuntu 22, following a successful lateral movement event. The attacker, originating from 192.168.1.100, established persistence using the pam_exec.so module and a custom binary located in /home/ubuntu/.local/shared. Data exfiltration was observed via a good.zip file, and a Discord bot was deployed as the Command and Control (C2) mechanism.

Anti-forensics activities included the deletion of log directories. The investigation leveraged Volatility3 to analyze memory artifacts, revealing critical timestamps, C2 infrastructure details, and the most recent attacker commands. This analysis provides a comprehensive timeline of the compromise and highlights key indicators of compromise (IOCs) for future detection and prevention.

192.168.1.100

Reasoning: Analysis of memory artifacts using strings $MEM | grep -i "ssh" revealed the originating IP address of the successful SSH authentication.

2. We observed network traffic containing a ZIP file named 'good.zip', indicating likely data exfiltration. After that, the attacker established a persistence mechanism before terminating their session. Identify the full filesystem path of this persistence artifact that grants the attacker access to the server.

/home/ubuntu/.local/shared

Reasoning: This path was identified as the location of the persistence mechanism, likely a malicious binary or script, based on memory analysis.

3. Determine the name of the well-known Linux module exploited by the attacker to maintain persistent access.

pam_exec.so

Reasoning: Using strings $MEM | grep -C 5 -iE "(authorized_keys|good\.zip|pam_exec)" revealed the pam_exec.so module, indicating its use for persistence.

4. Provide the inode number of the file containing the attacker's persistence configuration.

6293320

Key Takeaways & Security Insights

  • •
    Linux.Envars Plugin: This Volatility3 plugin is crucial for revealing environmental variables like PATH, USER, and HOME, which can expose C2 frameworks or unusual configurations.
  • •
    PyInstaller Binaries: Compiled standalone PyInstaller binaries are often packed into a single executable and extract their components into temporary directories (/tmp) before execution, a common technique for malware.
  • •
    LD_LIBRARY_PATH Abuse: Attackers can manipulate LD_LIBRARY_PATH to force applications (e.g., discord.py) to load malicious libraries from non-standard locations, such as temporary folders, facilitating code injection or persistence.
  • •
    _PYI_Archive_File Indicator: The presence of _PYI_Archive_File in memory or file paths can indicate the use of PyInstaller, which is a valuable forensic artifact for identifying packed executables.
  • •
    Pagecache Plugin for Metadata: The pagecache plugin in Volatility3 is powerful for extracting file system metadata, including inode numbers, installation times, permissions, and access times (ctime, mtime, atime), even if the original file system is unavailable.
