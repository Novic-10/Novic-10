This challenge focused on fundamental file analysis techniques, crucial for initial malware triage and digital forensics. Participants were tasked with identifying various file properties, including file types, operating system compatibility, packing methods, and unique hash values (MD5, SHA1, SSDEEP).

Key tools and methods employed included using the file command for type identification, md5sum and sha1sum for cryptographic hashing, ssdeep for fuzzy hashing, and UPX for unpacking compressed executables. The challenge highlighted the importance of understanding file metadata and characteristics to uncover hidden information or malicious intent.

Question & Answer Solutions

1. What is the name of the file that its md5 hash ends with "56e"? (Format: file.ext)

wire.bin

Reasoning: Used md5sum ./* to list all MD5 hashes and identify the file ending with 56e. The file command was used to determine the file type, and .bin was inferred as the extension.

2. What is the md5 hash value of the file named "DROP_B~1.bin"? (Format: MD5)

f7d236c4a75f9e0111f0a2d53b7cbc2e

Reasoning: The same method as Q1 was applied, using md5sum to find the hash for DROP_B~1.bin.

3. What is the file type of the file that its md5 ends with "318"? and what OS does this file run? (Format: Type, OS)

ELF, Linux

Reasoning: Identified the file using md5sum and then used the file command to determine its type and target OS.

4. How many of the files are identified to run in Windows Systems? (Format: Number)

5

Reasoning: Executed file ./* and counted the entries identified as Windows executables.

5. How many of the files are identified to run in Linux Systems? (Format: Number)

2

Reasoning: Executed file ./* and counted the entries identified as Linux executables (ELF).

6. How many files are upx packed? (Format: Number)

4

Reasoning: Used a hex editor (HxD) to search for the "UPX" string within the files, indicating UPX packing. Alternatively, upx -l could be used.

7. What is the name of the original executable file that, once restored and verified, has an MD5 hash ending with “348”? (Format: file.ext)

psamples1.bin

Reasoning: UPX-packed files needed to be unpacked first using upx.exe -d [filename]. After unpacking, md5sum was run on the restored files to find the one with an MD5 hash ending in 348.

8. What is the name of the original executable file that, once restored and verified, has an SHA1 hash ending with “80e”? (Format: file.ext)

712.bin

Reasoning: Similar to Q7, files were first unpacked using upx.exe -d, then sha1sum was used to find the file with the matching SHA1 hash ending in 80e.

9. What is the name of the file that its ssdeep hash ends with "12qW/"? (Format: String)

Ardamax

Reasoning: Used ssdeep ./* to generate fuzzy hashes for all files and then filtered for the hash ending with 12qW/.

10. What is the name of the file that its ssdeep hash value ends with "nV6V"? (Format: .something)

.DS_Store

Reasoning: Used ssdeep ./* to find the file with the matching fuzzy hash ending in nV6V.

11. What file contains a zip header? what is the hex that represents this file type? In hexadecimal format (Format: file.ext, 0x....)

an-sample.bin, 0x504B

Reasoning: A ZIP file header typically starts with the hexadecimal signature 0x504B. This was identified by inspecting file headers with a hex editor or using the file command which often identifies ZIP archives.

Key Takeaways & Security Insights

  • •
    Importance of Hashing: Cryptographic hashes (MD5, SHA1) are critical for uniquely identifying files and verifying their integrity. Fuzzy hashes (SSDEEP) are invaluable for identifying similar files, even if they have minor modifications, which is common in malware variants.
  • •
    File Type Identification: Tools like the file command are essential for quickly determining a file's format and intended operating system, which guides further analysis.
  • •
    Unpacking Executables: Malware often uses packers like UPX to compress and obfuscate its code. The ability to identify and unpack these executables is a fundamental step in static analysis, revealing the original, uncompressed binary for deeper inspection.
  • •
    Hexadecimal Signatures: Understanding common file magic numbers (hexadecimal signatures) allows for manual identification of file types, especially when file extensions are missing or misleading.
  • •
    Comprehensive Toolset: Effective file analysis requires a combination of command-line utilities (e.g., md5sum, sha1sum, ssdeep, file) and specialized tools like UPX unpackers and hex editors.
