This writeup details the investigation into the new Sysmon 14 feature: FileBlockExecutable. This powerful addition to Sysmon allows for preventative actions, specifically blocking executable files from being written to disk in specified locations. The exercise involved analyzing Sysmon operational logs to identify blocked file events, understand the initiating processes, and extract critical threat intelligence such as malware names and source URLs.

The primary objective was to explore how FileBlockExecutable can be configured and leveraged to enhance endpoint security, particularly in preventing the execution of malicious files dropped by browsers or other applications. We also examined a known limitation of this feature regarding temporary filenames and discussed potential future enhancements.

Question & Answer Solutions

1. In Sysmon 14, we can now use Sysmon configuration files to take preventative actions using the new feature, FileBlockExecutable. This allows us to prevent files from being written to specific locations! Open Event Viewer as an administrator (select the BTLO user if you receive a popup), and navigate to Microsoft > Windows > Sysmon > Operational. Filter on Event ID 27 to only see File Block Executable events. What is the timestamp of the first observed 27 event?

8/22/2022 3:55:16 PM

Reasoning: Navigated to Event Viewer, filtered the Sysmon Operational log for Event ID 27, and identified the timestamp of the earliest event.

2. In the first 27 event, what is the Image that initiated the file download?

C:\Program Files\Google\Chrome\Application\chrome.exe

Reasoning: Examined the details of the first Event ID 27 and extracted the Image field.

3. In the first 27 event, retrieve the SHA256 hash of the file that was blocked and search for it on URLHaus. Based on the tags, what is the name of this malware?

A310logger

Reasoning: Extracted the SHA256 hash from the event details and searched it on URLHaus. The tags on the URLHaus entry indicated the malware name.

4. If we wanted to create a new Sysmon configuration file that would prevent Microsoft Word from creating executable files (dropped from weaponized macros), what line would we use? (You do not need to include a Image 'name' property)

<Image Condition="image">winword.exe</Image>

Reasoning: To block executables created by Microsoft Word, the Image field in the Sysmon configuration should target winword.exe.

5. View the block-downloads-config.xml in the /Downloads/Sysmon/ folder. Review the logic to block all executables within the Downloads folder. What would be the re-written line to block files being written to the OS-level Temp directory?

<TargetFilename condition="contains all">C:\Windows\Temp</TargetFilename>

Reasoning: Based on the existing configuration for blocking downloads, the TargetFilename condition needs to be updated to target the C:\Windows\Temp directory.

6. Find the 27 event with the hash ending in B4A2. What is the TargetFilename (filename only, not path)

freeb13.dll

Reasoning: Filtered Event ID 27 events for the specified hash suffix and extracted the TargetFilename.

7. Search the hash on VirusTotal and look at the Community tab. What is the source URL?

http://safe-car.ru/lib/freebl3.dll

Reasoning: Searched the hash on VirusTotal and found the source URL listed under the Community tab.

8. One limitation of Sysmon 14's new blocking feature (as of 22/08/2022) is that files downloaded from a browser show the TargetFilename as the temporary file name, randomly generated by Windows. What is the name of the property that we hope to see in the near future, giving us better visibility over the file that was actually blocked?

OriginalFileName

Reasoning: This information was found in the blog post by Olaf Hartong, "Sysmon 14.0 FileBlockExecutable," which discusses the limitations and future enhancements of the feature.

Key Takeaways & Security Insights

  • •
    Proactive Threat Prevention: The Sysmon 14 FileBlockExecutable feature significantly enhances endpoint security by allowing organizations to proactively prevent malicious executables from being written to sensitive directories. This moves beyond detection to active prevention, reducing the attack surface.
  • •
    Granular Control: Sysmon configuration files enable highly granular control over which files are blocked and where. This allows security teams to tailor policies to specific organizational needs, such as preventing executables in user download folders or temporary directories.
  • •
    Threat Intelligence Integration: The ability to extract file hashes from blocked events and cross-reference them with threat intelligence platforms like URLHaus and VirusTotal is crucial for understanding the nature of blocked threats and enriching incident response efforts.
  • •
    Visibility Challenges: A current limitation of FileBlockExecutable is that browser-initiated downloads often show a temporary TargetFilename rather than the original filename. The anticipated addition of an OriginalFileName property would significantly improve forensic visibility and incident analysis.
  • •
    Continuous Improvement: The evolution of Sysmon, including features like FileBlockExecutable, highlights the importance of staying updated with security tool capabilities and understanding their nuances and limitations for effective deployment.
