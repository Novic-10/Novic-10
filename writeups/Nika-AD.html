Executive Summary & Overview

This CTF challenged us to analyze a sophisticated cyber-attack by "BlackCipher" against "CYPYRATE's" network, which disrupted critical operations. The attack chain began with initial access to the Web Server via an EternalBlue exploit. Following this, the attacker leveraged Kerberoasting to compromise the nrob user account, enabling lateral movement to the File Server via RDP. On the File Server, privilege escalation was achieved by exploiting weak service permissions using Powerview.ps1 and sc.exe to add nrob to the local Administrators group. Subsequently, mimikatz.exe was deployed to dump credentials, leading to further lateral movement to the IT Admin Workstation, likely using rzen's credentials. The final stage involved establishing persistence and control over the Domain Controller through a Golden Ticket attack, executed with PsExec64.exe. The investigation relied heavily on network packet analysis with Wireshark and log analysis with Splunk to reconstruct the attack timeline and identify specific TTPs.

Step-by-Step Investigation Workflow

1. Initial Reconnaissance & Attacker Identification

The investigation began by identifying the attacker's IP address and initial reconnaissance activities against the Web Server using Wireshark. 

ip.addr==192.168.1.12 && ip.addr==192.168.1.13 && tcp.flags.syn == 1 && tcp.flags.ack == 1

Filter for SYN/ACK packets between the attacker and web server to confirm initial connection attempts.

2. Identifying Targeted Service and Exploit

Further Wireshark analysis focused on common SMB ports to pinpoint the service targeted for initial access and the specific exploit used. 

ip.addr==192.168.1.12 && tcp.dstport in {445 4444 135 139}

Filter for traffic to common SMB/RPC ports from the attacker. 

ip.addr==192.168.1.12 && tcp.port == 445

Inspect SMB traffic for NTLMSSP challenges and PeekNamedPipe calls indicating EternalBlue.

3. Kerberoasting Attack Detection

Transitioning to Splunk, we searched for Kerberos service ticket requests to identify credential theft attempts against the Domain Controller. 

EventID=4768

Search for Kerberos Service Ticket Operations (Event ID 4768) to detect Kerberoasting.

4. Lateral Movement to File Server

After compromising a user, the attacker moved laterally to the File Server. Splunk was used to trace logon events for the compromised user. 

index=* host="FILE-SERVER" Account_Name=nrob TaskCategory=Logon Logon_Type=10 | sort + UtcTime

Filter for RDP (Logon Type 10) logons by the compromised user on the File Server.

5. Privilege Escalation on File Server

The attacker attempted privilege escalation on the File Server. We investigated PowerShell script block execution and process creation events. 

index=* host="FILE-SERVER" EventCode IN ("1", "4688", "4104", "4103") Image!="*splunk*" latest="05/18/2024:08:50:37" | sort - _time | table _time, EventCode, Image, CommandLine, ParentCommandLine, ParentImage, User

Search for process creation (Event 1, 4688) and PowerShell script block logging (Event 4104, 4103) to identify privilege escalation tools like Powerview. 

index=* host="FILE-SERVER" EventCode IN ("1", "4688") powershell.exe Image!="*splunk*" | sort + _time | table _time, Image, CommandLine, ParentCommandLine, ParentImage, User

Refine search to focus on PowerShell processes and their command lines to find service abuse.

6. Credential Dumping

After gaining elevated privileges, the attacker dumped credentials. We looked for known credential dumping tools in common temporary/download directories. 

index=* host="FILE-SERVER" "*\\Temp\\*" OR "*\\tmp\\*" OR "\\Downloads\\*" OR "\\*AppData\\*" OR "*\\ProgramData\\*" OR "*\\Tasks\\*" NOT "*splunk*"

Broad search for suspicious executables in common user-writable or temporary directories.

7. Further Lateral Movement & Persistence

Using newly dumped credentials, the attacker moved to another workstation and established persistence on the Domain Controller. 

index=* host="FILE-SERVER" EventCode IN ("1", "4688", "4104", "4103", "4624", "4625") Image!="*splunk*" earliest="05/18/2024:08:50:37" | stats count by User

Analyze user activity post-credential dump to identify new accounts used for lateral movement. 

index=* earliest="05/18/2024:08:56:32" CurrentDirectory="C:\\Users\\rzen\\*" | table _time, User, CommandLine, ParentCommandLine, host, Hashes

Search for activity related to the compromised user rzen, specifically for tools like PsExec.

Key Takeaways & Security Insights

  • Patch Management is Critical: The initial compromise via EternalBlue highlights the severe risks of unpatched systems, especially public-facing ones. Regular and timely patching is paramount.
  • Strong Authentication & Least Privilege: Kerberoasting and subsequent credential dumping underscore the need for strong, unique passwords for service accounts and enforcing the principle of least privilege across all user accounts.
  • Endpoint Detection & Response (EDR): The use of tools like Powerview.ps1 and mimikatz.exe, along with service abuse, demonstrates the importance of robust EDR solutions capable of detecting suspicious PowerShell activity, process injection, and credential dumping attempts.
  • Network Segmentation: The DMZ and internal network segmentation were present but the attacker was able to pivot. Proper segmentation and strict firewall rules between zones could have limited lateral movement post-initial compromise.
  • Log Monitoring & Alerting: Effective use of Splunk was crucial for this investigation. Comprehensive logging (especially PowerShell script block logging, process creation, and logon events) combined with proactive alerting is vital for early detection of malicious activities.
  • Service Hardening: The privilege escalation via weak service permissions emphasizes the need for regular security audits of service configurations and permissions to prevent exploitation.
