Executive Summary & Overview

MiddleMayhem Inc. experienced a targeted attack on their admin portal. The threat actor exploited a vulnerability in the Next.js framework to bypass authentication and gain initial access. This was followed by the upload and execution of a reverse shell, establishing remote code execution on the web application server. Subsequently, the attacker performed lateral movement by discovering SSH credentials and brute-forcing their way into the database server, ultimately achieving successful authentication. This writeup details the investigation using SIEM logs to reconstruct the attack chain and identify key indicators of compromise.

Step-by-Step Investigation Workflow

The investigation began by identifying the web application's framework and version, which led to the discovery of a critical CVE. Subsequent analysis of SIEM logs revealed the attacker's activities, from initial exploitation to lateral movement.

1. Initial reconnaissance and framework identification.

ps aux | grep -E "apache."
sudo ss -tulpn | grep -E ':(443|80)'

Used to identify running web services and ports. The website was found to be running on port 8080.

2. Identifying the Next.js framework and version via browser console.

window.next.version

Executing this JavaScript in the browser console revealed Next.js 15.0.0.

3. Discovering hidden administrative paths via robots.txt.

Navigating to /robots.txt revealed /admin and /admin/file-upload.

4. Identifying the attacker's IP address from SIEM logs.

index=* host=webapp http_response_code=200 ip_src="172.217.164.174"

Initial broad search for webapp activity, later refined to identify the attacker's source IP as 218.92.0.204.

5. Counting unique URIs accessed by the attacker.

index=* host=webapp ip_src="218.92.0.204" | stats dc(http_request_uri) as "Unique URIs Accessed"

This Splunk query revealed the number of distinct URIs accessed by the attacker.

6. Identifying CVE exploitation using the x-middleware-subrequest header.

index=* "x-middleware-subrequest" ip_src="218.92.0.204"

This query confirmed the use of the x-middleware-subrequest header, indicative of CVE-2025-29927 exploitation to bypass authentication.

7. Attacker accesses /api/upload after CVE exploitation.

index=* earliest="03/24/2025:11:06:34" ip_src="218.92.0.204"

Logs show the attacker accessing /api/upload, preparing for reverse shell upload.

8. Reverse shell payload upload and execution.

index=* host=webapp http_request_method="POST"

This query revealed the POST request containing the shell.sh payload. 

index=* host=webapp tcp_dstport=31337

Confirmed reverse shell establishment to 113.89.232.157:31337.

9. Lateral movement to dbserver via SSH.

index=* earliest="03/24/2025:11:06:35" host=dbserver

Logs show brute-force attempts and a successful SSH login to dbserver by user dbserv from the compromised webapp.

Key Takeaways & Security Insights

  • Vulnerability Management: Prompt patching of known vulnerabilities in web frameworks (e.g., Next.js) is critical. Regular scanning and monitoring for CVEs relevant to deployed technologies are essential.
  • Input Validation & Authentication Bypass: Robust input validation and secure authentication mechanisms are paramount. Exploitation of headers like x-middleware-subrequest highlights the need for comprehensive security testing beyond typical web application firewalls.
  • Endpoint Security & EDR: The ability to upload and execute arbitrary code (reverse shell) underscores the importance of endpoint detection and response (EDR) solutions to detect and prevent such activities.
  • SIEM & Log Analysis: Detailed SIEM logs are invaluable for incident response. The ability to correlate events across different hosts and identify specific indicators like HTTP headers, URI access patterns, and network connections is crucial for reconstructing attack chains.
  • Network Segmentation & Least Privilege: Lateral movement via SSH could have been mitigated with stricter network segmentation between the webapp and database servers, and by enforcing least privilege access for user accounts.
  • Credential Management: Brute-force attacks highlight weaknesses in password policies or credential management. Implementing strong, unique passwords and multi-factor authentication (MFA) for critical services like SSH is vital.
