Executive Summary

This challenge focused on identifying and exploiting exposed .git directories on web servers to extract sensitive information. We utilized tools like gitdumper.sh to clone exposed repositories and git log commands to analyze commit history for passwords, sensitive files, and other valuable artifacts. The exercise highlighted the critical importance of properly securing version control repositories, especially in production environments.

Key findings included a Spring Boot application password and an SSH private key (id_rsa) mistakenly committed to a repository, demonstrating common developer misconfigurations that can lead to significant security vulnerabilities.

Question & Answer Solutions

1. Use GitTools, where is the git directory located in website A?

/.git

Reasoning: This is the default directory for Git repositories, commonly exposed if not properly secured.

2. What is the springboot password?

noP@sX3211

Reasoning: The password was discovered by analyzing the Git commit history. Using git log -p -i -S "password" revealed the latest commit containing the password. Further investigation with git log -p -- src/main/resources/application.properties showed the original password within the application properties file.

3. Website B is using Wordpress. Which nuclei template is useful in detecting exposed git directory?

wordpress-git-config.yaml

Reasoning: After using ./gitdumper.sh http://wp.sbt/.git/ ~/Desktop/wp_site to extract the repository, a search within the Nuclei templates folder using grep -R "wordpress" helped identify relevant templates, with wordpress-git-config.yaml being the most appropriate for detecting exposed Git configurations in WordPress installations.

4. Where is the git directory located in website B?

/wp-content/themes/.git

Reasoning: Knowledge of the typical WordPress directory structure, where themes are located in /wp-content/themes/, helped pinpoint the exposed Git repository within a theme's directory.

5. Commit messages can be interesting sometimes as an attacker. What’s here?

rX3dea78sdummY43sZ

Reasoning: By inspecting individual commit information using git show <commit Number>, a sensitive string was found within a commit message, highlighting the risk of including sensitive data even in commit logs.

6. Some sensitive file seems to be mistakenly committed, what is it?

id_rsa

Reasoning: Using the command git log --all --name-only --oneline, which lists all committed files across all branches, the id_rsa (SSH private key) file was identified as having been mistakenly committed to the repository.

Key Takeaways & Security Insights

  • •
    Secure Git Directories: Always ensure that .git directories are not publicly accessible on production web servers. Misconfigurations can lead to full repository disclosure.
  • •
    Commit Hygiene: Never commit sensitive information such as passwords, API keys, or private SSH keys (id_rsa) to version control, even temporarily. Use environment variables, secret management tools, or .gitignore to prevent accidental commits.
  • •
    Git Log Analysis: The git log command with various flags (-p, -S, --name-only) is a powerful tool for forensic analysis, allowing attackers (and defenders) to trace changes and uncover hidden sensitive data.
  • •
    Default Locations: Be aware of common default Git directory locations, such as /.git for root repositories and specific paths like /wp-content/themes/.git for CMS-specific installations.
  • •
    Master Log Files: The master log files are located at /.git/logs/refs/heads/master, which can provide a detailed history of changes to the master branch.
  • •
    Automated Scanning: Tools like nuclei can be effective for automated detection of exposed Git directories and other common web vulnerabilities, emphasizing the need for proactive security scanning.
