Executive Summary & Overview

This challenge, "Anakus," from Blue Team Labs Online, simulates a malware analysis assessment for a prospective Malware Analyst role at Tesserent. The scenario involves Loda Sukana, tasked with analyzing "Threat logs" and "Malware(s)" within a provided virtual machine environment. The objective is to demonstrate proficiency in reverse engineering and incident response techniques to identify and analyze malicious artifacts.

The investigation focuses on two primary suspicious files: lnrvmp.dll and hataker.exe. Utilizing a suite of forensic tools such as Detect It Easy, SigCheck, TCPview, and Timeline Explorer, the analysis uncovers critical details about the malware's characteristics, its attempts at evasion, network communication patterns, and the broader impact observed in system logs. The challenge emphasizes practical application of static and dynamic analysis to identify threats and map them to MITRE ATT&CK techniques.

Question & Answer Solutions

1. Using Detect it Easy, what is the SHA256 hash of the malware in question (lnrvmp.dll), and what language was it written in? Feel free to utilize VirusTotal to garner more information (Format: SHA256, Language)

fb20fc4e474369e6d8626be3ef6e79027c2db3ba0a46f7b68c6981d6859d6d32, C/C++

Reasoning: The Get-FileHash cmdlet was used to obtain the SHA256 hash of lnrvmp.dll. Detect It Easy and VirusTotal confirmed the language as C/C++.

2. The total entropy value in Detect it Easy gives us a general indication of the randomness across the entire file, but the presence of a highly entropic-packed section indicates a portion of the file containing data that has been compressed—packed. Usually, an entropy above 7.2 is considered malicious, what is the name of this section in question? (Format: .xxxx)

.rsrc

Reasoning: Analysis of the file's sections in VirusTotal (or Detect It Easy) revealed that the .rsrc section had an entropy value exceeding 7.2, indicating potential packing or obfuscation.

3. Given the file’s entropy level, reputation on VirusTotal, and weird characteristics, it is clear that is malicious. However, attackers will sometimes use the names of security companies in their malware to bypass detection. In this case, what product name is this malware impersonating? (Format: Product Name)

Sophos Anti-Virus

Reasoning: The SigCheck.exe -a lnrvmp.dll command was used to inspect the file's embedded information, revealing it was attempting to impersonate "Sophos Anti-Virus".

4. Using SigCheck, let's see if the file has been signed with a code-signing certificate—proving its validity. Include the “Verified” status and “Signing date” also known as Link Date (Format: Status, X:XX PM X/X/XXXX)

Unsigned, 4:59 PM 9/1/2022

Reasoning: Executing SigCheck.exe -a lnrvmp.dll showed that the file was Unsigned and had a Link Date of 4:59 PM 9/1/2022.

5. Let’s look at the alleged malware “hataker.exe”. Judging from its hash, it is not apparent on most malware platforms—albeit, it does not exclude its maliciousness. Turn on Windows Defender and run the malware until it picks it up. What is the name given to this alleged, malicious trojan-type program? (Format: Trojan:full name)

Trojan:Win32/Meterpreter.RPZ!MTB

Reasoning: Windows Defender was enabled in the VM's system settings. Upon executing hataker.exe, Windows Defender detected it as Trojan:Win32/Meterpreter.RPZ!MTB.

6. Interestingly, now knowing the trojan type for the “hataker.exe”, we can safely assume the attacker was planning to initiate a connection from the victim’s endpoint to its command and control server. What is this method called? (Format: Xxxxxxx Xxxxx)

Reverse Shell

Reasoning: A Meterpreter payload is commonly used to establish a reverse shell, allowing an attacker to gain remote control over a compromised system by having the victim initiate the connection.

7. Sticking to the same context, let’s dissect the malware further. What dynamic domain is the malware “hataker.exe” using to establish a connection back to the attacker’s system? (Format: Domain name)

0.tcp.ngrok.io

Reasoning: Running TCPview while hataker.exe was active revealed an outgoing connection to an IP address. A quick lookup of this IP on VirusTotal identified the associated dynamic DNS domain as 0.tcp.ngrok.io.

8. Using Timeline Explorer, look at the “Threat Logs” from the incident, how many high-risk alerts were tracked? (Format: Count)

6

Reasoning: The Log_threat.csv file was opened in Timeline Explorer and filtered by the "High" risk level, showing a total count of 6 alerts.

9. What are the two “Rule Titles” with the highest count under the high-risk alerts level group—in respective order? (Format: Rule Title 1, Rule Title 2)

Important Log File Cleared, Important Windows Service Terminated With Error

Reasoning: Within Timeline Explorer, after filtering for high-risk alerts, these two rule titles appeared with the highest frequency (2 counts each).

10. Examine the last “Rule Title” for the high-risk alerts level group: what MITRE ID does this correspond to and what is the TgtGrp in question? (Format: TechniqueID, TgtGrp)

T1098, Administrators

Reasoning: The last high-risk alert, "User added to local group," indicated the TgtGrp as Administrators. Researching this activity points to MITRE ATT&CK Technique ID T1098 (Account Manipulation).

11. Looking at the medium-risk level alerts, what is the “Rule Title” and count of the popular alert group? (Format: Rule Title, Count)

Potentially Malicious PwSh, 457

Reasoning: Filtering the Log_threat.csv in Timeline Explorer for medium-risk alerts showed "Potentially Malicious PwSh" as the most frequent rule title with a count of 457.

12. What function was used for the password spray attack? Lists its MITRE ID for this type of attack as well (Format: powershell-function, TXXXX.xxx)

Invoke-LocalPasswordSpray, T1110.003

Reasoning: The "Potentially Malicious PwSh" alerts (from Q11) indicated the use of the PowerShell function Invoke-LocalPasswordSpray. This technique aligns with MITRE ATT&CK Technique ID T1110.003 (Password Spraying).

Key Takeaways & Security Insights

  • •
    Importance of Static Analysis: Tools like Detect It Easy and SigCheck are crucial for initial triage, identifying file characteristics (hash, language, entropy, signing status), and uncovering attempts at impersonation. High entropy sections often indicate packing or obfuscation, a common malware tactic.
  • •
    Dynamic Analysis for Network Activity: Executing suspicious binaries in a controlled environment and monitoring network connections with tools like TCPview is essential to identify Command and Control (C2) infrastructure, such as dynamic DNS services like ngrok.io, which attackers use for covert communication.
  • •
    Endpoint Detection and Response (EDR) Capabilities: Enabling and observing Windows Defender's detection capabilities provides immediate insights into the malware's classification (e.g., Trojan:Win32/Meterpreter), confirming its malicious intent and type.
  • •
    Log Analysis for Incident Context: Tools like Timeline Explorer are vital for reviewing threat logs, identifying high and medium-risk alerts, and understanding the sequence of events during an incident. This helps in correlating malware activity with system-level changes.
  • •
    MITRE ATT&CK Framework: Mapping observed attacker techniques (e.g., Account Manipulation T1098, Password Spraying T1110.003) to the MITRE ATT&CK framework provides a standardized way to describe and understand adversary behavior, aiding in defensive strategies.
  • •
    Common Attack Techniques: The challenge highlighted several common attack techniques, including the use of reverse shells (e.g., Meterpreter), impersonation of legitimate software, and credential access methods like password spraying via PowerShell functions.
